A handful of crop and export-dialog edge cases from a code sweep are fixed: a headless render now validates a job's project (crop, transform, clip ids, track references) before rendering, instead of silently dropping a clip with a malformed crop — and, for a project that carries no resolution of its own, still falls back to the source's own size rather than quietly rendering at 1920x1080; a Shift-locked crop drag that would exceed the 90% inset limit now slides to that limit with the locked ratio held, the same way an unlocked drag already stops at its own limit, instead of landing a clamp that silently broke the ratio; a corrupt zero, negative, or NaN clip scale no longer divides the crop drag's own arithmetic by it; and the export dialog says "WebM needs this tab visible" in every browser that will actually export WebM — including one with no MP4 support, and including a restored MP4 preference that falls back to WebM — while saying nothing when WebM cannot run either.

Two findings turned out not to be bugs and are now pinned with regression tests instead: the crop handles' drag listeners already survive the layer rendering nothing mid-drag (only an actual unmount tears them down), and nothing in this build's render paths reaches the editor's base64 GIF entry point, so the README's memory estimate stands with a clarifying note about which path it describes. The arrow-key crop nudge's documentation is also corrected: it moves a handle's fixed insets in the clip's own (unrotated) frame, not "the way the arrow points" on a rotated clip.
