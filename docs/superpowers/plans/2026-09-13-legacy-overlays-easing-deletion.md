# Legacy overlays → clips, per-keyframe easing, and the dead-editor deletion (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** close the two capability gaps the dead-code verification found before deleting the two dead components. Unlike #331/#342/#345/#349 this is **feature work with behaviour change**, so each task states the behaviour, the tests that pin it, and the docs — and the one bug (legacy overlays silently dropped from every export) is pinned red before it is fixed. Requirements are tracked as ESCSUITE-46 (R1) and ESCSUITE-47 (R2).

## Requirements

- **R1** — Legacy overlays carried by a loaded project (`timeline.textOverlays` / `timeline.shapeOverlays`) must be listable, selectable, editable, movable in time, deletable and **included in every export**, which this plan satisfies by converting them into ordinary overlay clips on load (in the store *and* in the headless render entry) and emptying the arrays.
- **R2** — A keyframe's easing must be selectable per keyframe in the keyframe panel, which today hard-codes `'ease-in-out'` on creation (`KeyframePanel.tsx:153`) and only preserves whatever is already stored (`:175`).

## Current structure

**The load funnel.** Every production load path reaches one function. `setProject` (`apps/artist/src/store/projectStore.ts:176-179`) is `project: ensureTimelineHasTracks(project)` plus a history push, and its four production callers are `app/useProjectActions.ts:90` (Open Project from disk), `components/VideoUploader.tsx:133` (project from the media library), `app/useSessionRestore.ts:60` ("Resume Previous Session?") and `app/useHostIntegration.ts:60` (the host's `LOAD_PROJECT`). `ensureTimelineHasTracks` (`projectStore.ts:1605-1670`, the only call site is line 177) fills in `resolution`, guarantees `timeline.tracks`, and **copies the two legacy arrays straight through** (`:1620-1621`, `:1632-1634`, `:1667-1668`). `core/projectManager.ts` checks a file-format `version` (`:129-132`) and migrates nothing. `core/storage.ts`'s `SessionState` (`:33-40`) persists `project` whole, so a legacy array survives autosave indefinitely.

**Where legacy overlays are read today.** Preview only: `Preview/PreviewPlayer.tsx:43-44` subscribes to both arrays and passes them into the scene at `:169-170`; `Preview/drawFrame.ts:311-334` draws every shape whose `[startTime, endTime)` contains the time, then `:335-353` every text, **after all clips and transitions**, with `scaleX/scaleY: 1`, `rotation: 0` for text and `blur: 0` for both. Nothing else reads them: `grep` over `core/canvasRenderer.ts`, `core/exportWebM.ts`, `core/exportMP4.ts`, `core/exporter.ts` for `textOverlays|shapeOverlays` returns nothing — the exporters iterate `timeline.clips` and branch on `clip.overlayType`. `store/selectors.ts:29-30` (`selectTextOverlays`/`selectShapeOverlays`) has no importer at all.

**The headless path does not go through the store.** `apps/artist/src/headless/main.ts` exposes `window.__renderProject` / `window.__renderProjectToFile`; `headless/renderProject.ts`'s private `render()` takes `input.project` and hands `project.timeline.clips` / `.tracks` / `project.resolution` straight to `exportToMP4`/`exportToWebM`. No `setProject`, no `ensureTimelineHasTracks`. `services/headless-artist/src/renderDriver.ts` only ferries the JSON into the page. So a legacy overlay is dropped twice over: once in the editor's export, once in the kit's.

**Overlay clips as they exist.** `addTextOverlayClip` (`projectStore.ts:935-990`) and `addShapeOverlayClip` (`:993-1063`) are what `ClipEditor/useClipEditorActions.ts:332-338` (`handleAddText`/`handleAddShape`) call. Both: `id: uuidv4()`, `sourceVideoId: ''`, `startTime: 0`, `endTime: duration`, `duration: 5` by default, `timelinePosition: position ?? currentTime`, `blendMode: 'normal'`, `transform/effects/transition` = the three `DEFAULT_*` spreads, `overlayType`, and `textData: { ...DEFAULT_TEXT_OVERLAY_DATA, ...textData }` / `shapeData: { ...DEFAULT_SHAPE_OVERLAY_DATA, ...shapeData }`. Track choice: `findEmptyTrack(tracks, clips)` (`:92-98`, lowest-index track with no clips) else `createTrackAtTop(tracks, name)` (`:77-89`, `index = max(index)+1`, `visible: true, locked: false, muted: false, volume: 1, height: 60`). `addShapeOverlayClip` additionally overrides `fillColor: '#00000000'`, `strokeWidth: 0`, `blurAmount: 10` when the type is `'blur'` (`:1027-1034`) and names the clip `'Blur Region'`.

**The types.** `TextOverlayData` (`store/types.ts:156-172`) is `TextOverlay` (`:226-241`) minus `{id, startTime, endTime, opacity}` plus optional `{rotation, scale}`. `ShapeOverlayData` (`:194-209`) is `ShapeOverlay` (`:243-257`) minus the same four plus optional `blurAmount`. `Timeline` (`:329-335`) declares both arrays non-optional.

**The seven legacy mutators + the selection state.** `addTextOverlay` `:1117`, `updateTextOverlay` `:1148`, `removeTextOverlay` `:1166`, `addShapeOverlay` `:1181`, `updateShapeOverlay` `:1212`, `removeShapeOverlay` `:1230`, `setSelectedOverlay` `:1257` (declared `types.ts:465-470,479`); state `selectedOverlayId`/`selectedOverlayType` (`types.ts:396-397`, initial `:158-159`, reset `:189-190`). They are **written** by `resetProject`, both `add*Overlay`, both `add*OverlayClip` (`:988-989`, `:1061-1062`), both `remove*Overlay`, `setSelectedClipId` (`:1249-1255` — `selectedOverlayId: id ? null : undefined`) and `setSelectedOverlay`; **read** by nothing outside `OverlayEditor.tsx` and the store's own guards. No production caller of any of the seven.

**KeyframePanel.** `KeyframePanel.tsx` (324 lines) owns `handleAddKeyframe` (`:131-155`, easing hard-coded `'ease-in-out'` at `:153`), `handleKeyframeValueChanged` (`:158-177`, reads fresh state via `useEditorStore.getState()` and preserves `existingKf?.easing || 'ease-in-out'` at `:175`) and `handleDeleteKeyframe` (`:180-184`); it renders `<KeyframeGraph>` inside `div.graphContainer` when a property is selected (`:225-251`). `KeyframeGraph.tsx` (467 lines) already owns the per-keyframe selection: `const [selectedKeyframeTime, setSelectedKeyframeTime] = useState<number|null>(null)` (`:60`), set at `:200` (mousedown, guarded by `isCustomKeyframe` at `:195`), `:215` (click, same guard), `:324` (drag end), cleared at `:234` (Delete) and `:340` (background click); `isCustomKeyframe` is `:80-83`. **Its whole return is a bare `<svg ref={svgRef} className={styles.graph} …>` (`:366-373`)** — there is no HTML element in it, which is why the easing `<select>` cannot simply go "next to the delete affordance". `EASING_TYPES` (7 options) lives in `ClipEditor/clipEditorOptions.ts:54-62`, wired only to the animate-in/out presets. `setClipKeyframe` (`projectStore.ts:691-767`) **replaces by time** (`:698-704`, ±0.001) — so `{...existing, easing}` needs no new store action. The dead `ClipEditor/KeyframeEditor.tsx:117-126` is exactly that handler.

## Task B: per-keyframe easing in the keyframe panel
- [ ] **Branch `feat/keyframe-easing`.**

  **Behaviour.** Open the keyframe panel, click a property track to open its graph, click a keyframe: a labelled easing `<select>` appears below the graph showing that keyframe's current easing; changing it writes the keyframe back with the new easing and the same `time` and `value`. Deselecting (graph background click, Delete) hides it. Preset keyframes are already unselectable (`KeyframeGraph.tsx:195`, `:213-217`), so the control only ever addresses a custom keyframe — pin that rather than adding a `disabled` state. New keyframes still default to `'ease-in-out'` (`KeyframePanel.tsx:153`) and a value drag still preserves the stored easing (`:175`); neither line changes.

  **Why here and not in `KeyframePanel.tsx`.** `KeyframeGraph` already owns `selectedKeyframeTime` and uses it for delete; lifting that state into the panel to render the select in `div.graphHeader` would touch five `setSelectedKeyframeTime` call sites and add a new prop *and* new panel state. The smaller change keeps the selection where it is. But `KeyframeGraph` returns a bare `<svg>` (`:366`), which cannot hold an HTML `<select>` without a `foreignObject` — so **wrap the existing `<svg>` in `<div className={styles.graphWrap}>`, leaving the `<svg>`'s `ref`, `className={styles.graph}`, `viewBox`, `preserveAspectRatio` and both handlers byte-unchanged** (`KeyframeGraph.test.tsx`'s `measureGraph()` resolves `.${graphStyles.graph}` as an `SVGSVGElement` and must keep resolving to the svg), and render the select as the svg's sibling.

## Risks
**Stacking order is the subtle one.** Legacy overlays draw *after* every clip and every transition — shapes first, then text — so they are unconditionally on top. Converted clips are drawn by track index, so the conversion must place them above every existing track, shapes below text, and the array order must survive within a track. The plan's rule (shapes then texts, pool tracks reused only when times do not overlap, new tracks always at `max+1`) does that, and `getClipsAtTime` plus a stable sort preserve array order within a track — but a "tidier" implementation that puts all overlays on one reused empty track (the way `addTextOverlayClip` does via `findEmptyTrack`) would drop them *underneath* media clips on higher tracks and silently change every such project's picture. **Do not reuse `findEmptyTrack` here**; that is why the conversion does its own placement.

**Id collisions and the both-shapes project.** Derived ids (`legacy-text-<id>`, `legacy-shape-<id>`) could in principle collide with an existing clip id; the skip-if-present guard turns a collision into the right answer (already converted) rather than a duplicate, and makes the function idempotent for a file that somehow carries both legacy arrays and converted clips. Emptying the arrays is what makes the common case a one-shot. Track ids (`legacy-overlay-track-N`) must skip ids already on the timeline.

**Session snapshots.** `buildSessionSnapshot` persists `state.project` whole, so a session autosaved *before* this change still holds legacy arrays; it comes back through `useSessionRestore` → `setProject` → conversion, so it heals on the next restore. Worth one test, and worth remembering that a user's stored session will change shape on their next launch — that is the intended behaviour, not a migration to write.

**Degenerate legacy data.** `endTime <= startTime` and negative `startTime` are reachable in old files (nothing validated them); the clamps (`0.1` duration, `0` position) match what `OverlayEditor`'s deleted numeric inputs enforced. An overlay whose window sits past the current `timeline.duration` now extends the timeline, because the conversion recomputes duration — that is the point (it is what gets it exported), but it means a loaded project's visible length can grow.

**The headless kit fixture.** `apps/e2e/fixtures/headless/project.json` and `services/headless-artist/test/fixtures/manifest/project.json` carry no legacy arrays, so the conversion must be provably inert on them — the identity return for empty/absent arrays is what guarantees byte-identical output, and `pnpm --filter @escapesuite/headless-artist test:run` is the check.

**The preview tests are the trap in Task C.** `PreviewPlayer.overlays.test.tsx:297-378+` looks like a test of a deleted feature and is actually the best regression suite Task A has. Rewriting it to seed through `setProject` keeps its pixel assertions meaningful; deleting it would remove the only end-to-end evidence that a converted overlay draws where the legacy one drew. If one of those numbers moves during the rewrite, that is a conversion bug to fix, not an expectation to update.

**Coverage arithmetic cuts both ways.** Deleting 138 fully-covered functions lowers the functions percentage (~−0.10pp against ~0.97pp of headroom) while raising branches (~+0.49pp, because both files are branch-poor). Do not size any of this from `apps/artist/coverage/coverage-summary.json` as it stands — it is a partial run reporting 89.86% branches, below the floor. Re-measure.

**`KeyframeGraph`'s root element.** Wrapping the `<svg>` in a `<div>` is the whole of Task B's structural risk: `KeyframeGraph.test.tsx`'s `measureGraph()` resolves `.${graphStyles.graph}` and types it `SVGSVGElement`, and `screenToSvgCoords` measures `svgRef.current.getBoundingClientRect()`. Keep `styles.graph` and the `ref` on the `<svg>`; give the wrapper a new class. A `foreignObject` inside the svg would avoid the wrapper and is worse — it does not lay out reliably in jsdom and would make the select untestable.
