# ESCAPEARTIST App decomposition (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `apps/artist/src/App.tsx` (1,037 lines: one component holding the whole editor shell — 17 `useState` slots, 41 `useEditorStore` selector calls, 12 `useCallback` handlers, six effects that between them own the theme, the session restore prompt, the debounced session autosave and its store subscription, a 247-line window `keydown` cascade, the timeline's drag-to-resize document listeners, and the entire host-integration surface, then ~304 lines of JSX from line 731) into focused modules with **no behaviour change**, the way `ClipEditor` was split (#345), `Timeline` before it (#342) and `PreviewPlayer` before that (#331). The contract is the existing App suite — `App.test.tsx`, `App.messages.test.tsx`, `App.project.test.tsx`, `App.rerender.test.tsx`, `App.session.test.tsx`, `App.shortcuts.test.tsx`, 146 tests — passing **byte-unchanged**: no import path in them even needs to move, because `App.tsx` stays at `src/App.tsx` with its default export, `src/App.module.css` stays one stylesheet, and every `vi.mock` target stays where it is. Each task's reviewer diffs every moved block against the original.

## Smells to carry (do not fix)
- **`showNotification`'s timer is never cleared and never cancelled.** Each call opens a fresh `setTimeout(… , 3000)` and none of them is stored; a second notification inside three seconds leaves the first timer running, so it blanks the newer message early, and a notification issued just before unmount calls `setNotification` on a gone component.
- **Effect 4's body reads `clips` but its deps carry only `clips.length`.** Ctrl+B does `clips.find(c => c.id === selectedClipId)` against whatever array the handler last closed over, so an in-place edit that leaves the count unchanged leaves the split reading a stale clip. Keep the deps array exactly as it is.
- Effect 5's deps are `[isResizing, timelineHeight]`, so both document listeners and both `document.body.style` writes are torn down and redone on every clamped pixel of a drag. That churn is also the mechanism by which `handleResizeEnd` sees the final height — it is load-bearing, not waste.
- `handleNewProject` fires `clearSessionState()` without awaiting or catching it; a rejection is an unhandled promise rejection. Same shape as `saveSessionState(...).catch(console.error)` two effects up, which *does* catch.
- The `?loadVideo=` path calls `URL.createObjectURL(thumbnailBlob)` (694) and nothing ever revokes it.
- Effect 6 has `[]` deps while closing over `addSourceVideo`, `setProject`, `showNotification` and `urlParams`. `GET_STATE` works around it with an explicit `getState()` and a comment; `LOAD_VIDEO`, `LOAD_PROJECT` and the three URL paths do not, and rely on those four being stable. Keep the `[]`.
- `LOAD_PROJECT` does `setProject(message.payload as any)` with no validation — and it is the *same* unchecked shape that makes the project-manager double's `{ project: {} }` log "Load failed" in the tests described above.
- `formatTimeForNotification` is a one-line pass-through to `formatTime`. Keep the indirection; three call sites read better for it.
- The Escape cascade's first branch (the shortcuts sheet) returns **without** calling `preventDefault()`, while all three branches below it call it. `App.shortcuts.test.tsx` pins the ordering, not the `preventDefault`.
- Four different idioms for "show this conditionally" coexist in the JSX: `<ExportDialog isOpen/>`, `<KeyboardShortcuts isOpen/>`, `<ProjectLoadDialog isOpen/>`, `{notification && …}`, `{!inspectorCollapsed && <ClipEditor/>}`, and `<KeyframePanel/>` rendered unconditionally deciding for itself. Do not unify them.
- `parseUrlParams` returns `projectData` and `autoPlay`, which `App` destructures nothing out of and nothing applies — already documented as reserved names in `apps/artist/CLAUDE.md`.

## Risks
The hard part here is not the ref graph — `App.tsx` has no refs — it is **effect order and one invisible performance contract**. First, effect 2 writes `sessionRestored` and effect 3 gates on it, so registering the autosave hook before the session hook changes which render first arms the debounce; `App.session.test.tsx`'s "writes nothing before the debounce elapses" and "clears the pending write on unmount" are the net, and they are timing-sensitive under `toFake: ['setTimeout','clearTimeout']` with real `setImmediate` underneath. Second, and worse: **`App` must not subscribe to `currentTime`**. Four `getState().currentTime` reads and one `useEditorStore.subscribe` are all that stand between the current design and a full-tree re-render every ~200 ms of playback, and a well-meaning hook that turns any of them into a selector passes all 53 shortcut tests, all 7 session tests and all 32 project tests, failing only the single `toBeLessThanOrEqual(1)` in `App.rerender.test.tsx` — which reads like flake if you are not expecting it. That file also spies on `./hooks/useVirtualizedTimeline` by module namespace, so nothing about that path may move. Third, effect 4 is 247 lines of ordered `if`s where the order *is* the semantics: `c` before ctrl+c would never fire, `v` before ctrl+v would break paste, `o` before ctrl+o would break Open, and the Escape cascade has four levels that four separate tests assert in sequence. Move the block as one unit; do not "clean up" a single early `return`. Fourth, effect 6's `[]` deps become suspicious to a linter the moment its closed-over values are hook parameters — `eslint-plugin-react-hooks` 7.1.1's flat recommended config is in play and `lint` must be 0, so expect to need one scoped disable comment rather than a deps array. Fifth, the two lazy `useState` initialisers (`parseUrlParams` as a bare reference, and `timelineHeight`'s arrow) are easy to accidentally call eagerly when they move into a hook; `parseUrlParams()` per render would re-read the URL every time and quietly defeat the "read once at startup" contract the CLAUDE.md documents. Sixth, `src/App.module.css` is imported directly by `App.project.test.tsx` and queried through `styles.menuBackdrop`, so the stylesheet cannot be split even though nine components will now import it from `../App.module.css`. Finally, the coverage arithmetic: `App.tsx` is 100% lines and 100% functions today and carries 6 uncovered branches; splitting it into eighteen new files adds eighteen-plus functions to a denominator with roughly sixteen functions of slack, so any component that ships without its own test file — or any prop default that no test reaches — turns `test:coverage` red before a reviewer sees the diff. And do not size that slack from the `coverage-summary.json` currently on disk; it is a partial run reporting branches *below* the floor.
