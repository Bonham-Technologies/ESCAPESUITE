**Global constraints**
- No behaviour change. ClipEditor tests not edited except import paths / verbatim moves. Any assertion change is a finding, not a fix.
- Each extracted module or hook gets its own unit test file with concrete assertions (moved cases + direct tests of every export). Artist coverage floors (lines 99 / statements 98 / branches 90 / functions 98 after the Timeline work) hold; branches has the least headroom — **every optional prop with a default is a new branch**, so prefer required props, and cover any branch you do introduce.
- No new state; refs stay refs; effect order and deps arrays preserved (there are no effects here — so this reduces to: `useCallback`/`useMemo` deps arrays move verbatim, including the ones that are wrong, plus the appended ref/props objects that became parameters).
- No new store subscriptions, and no merging of the two that already exist for the same data (`scaleLocked` 99–103 vs `selectSelectedClip` 113). Extracted section components take props; they never call `useEditorStore`.
- **DOM identical.** Same elements, same order, same class names, same `title`/`placeholder`/`min`/`max`/`step`. Extracted components import the *same* `./ClipEditor.module.css` (keep the new files in `src/components/ClipEditor/`, flat, so the specifier does not change). No new wrapper elements — `rowControl` walks `label.parentElement`.
- **Positional reconciliation is behaviour.** `CollapsibleSection` holds its open/closed state and only reads `defaultOpen` at mount. Keep each `{cond && <Section/>}` guard in `ClipEditor.tsx` at its current child position; do not move the condition inside the new component and do not add `key={selectedClip.id}`, or sections would reset when the selection changes.
- Files ≤ ~600 lines. Lint 0, typecheck clean incl. `tsc -b --noEmit`, ES2020 lib so no `Array.prototype.at`. `pnpm --filter @escapesuite/artist test:coverage` green per task.

## Smells to carry (do not fix)
- `handleGoToClip` (179–182) reads `selectedClip` but its deps are `[clipPosition, setCurrentTime]` — a missing dependency. Move it verbatim.
- `setScaleLocked` (104–111) calls `useEditorStore.getState()` three times and re-finds the clip instead of using `selectedClip`; its deps are `[]`.
- Two subscriptions compute the same thing: the `scaleLocked` selector (99–103) re-finds the clip that `selectSelectedClip` (113) already selects. Do not merge them.
- `fillAlphaPercent`'s expression runs twice per render (slider `value` 619 and the `%` label 626). One helper, called twice — do not hoist to a memo.
- Two Reset buttons in Transform with different meanings: the section-header one (284–311) resets x/y/scale/opacity **and** overlay position data but not rotation; the scale one (834) spreads `DEFAULT_TRANSFORM` (rotation and `scaleLocked` included) and is the only one with a `title`. `ClipEditor.test.tsx` distinguishes them by that `title`'s absence.
- `handleResetTransform` hard-codes the shape defaults `0.2/0.2/0` (306–308) rather than importing a constant.
- Font size: `Math.max(8, parseInt(v) || 48)` means an empty field jumps to 48 and `4` clamps to 8, while the `max={200}` attribute is never enforced in code.
- Text background colour always forces alpha `cc` (529), discarding any alpha the user had; shape fill preserves alpha (576–581). Inconsistent, both pinned by tests.
- Shapes have two blur controls writing the same `blurAmount`: "Blur Amount" (1–50, `?? 10`) inside the blur-type branch 554–566, and the generic "Blur" row (0–50, `?? 0`) at 684–696 that renders for every shape type including `blur`, with a hint telling the user to make the fill transparent.
- Transform Pos X/Y uses `isOverlay && textData` for the displayed value but `isTextOverlay`/`isShapeOverlay` for the write (719–753) — asymmetric predicates that would disagree for a text clip carrying `shapeData`.
- `isVideo = !isOverlay && !isImage && !isAudio` (151), so a clip whose source is missing is labelled "Video Clip" and gets the Split button.
- The `<textarea>` writes `el.style.height` imperatively from `onChange` and `onFocus` (447–459); `ClipEditor.overlay.test.tsx` pins the resulting `'0px'` under jsdom.
- `clipTypeLabel` is a `let` + if/else ladder (398–403) computed after the early return, so it cannot be a `useMemo` without changing hook order.
- `KeyframeEditor.tsx` (272 lines) in this directory is imported by nothing but its own 18-test file — the live editor is `src/components/KeyframePanel/`. **Out of scope:** do not delete it in this refactor; raise it as a separate dead-code finding.

## Relation to OverlayEditor
`OverlayEditor.tsx` (1,058 lines) is the same shape one level of indirection away: one dispatcher (7–284) over four near-identical form components — `TextOverlayClipEditor` (295–495), `ShapeOverlayClipEditor` (506–687), and the legacy-array twins `TextOverlayEditor` (697–868) and `ShapeOverlayEditor` (878–1058). It duplicates ClipEditor's value maths outright: the same `Math.max(8, parseInt(e.target.value) || 48)` font clamp (346, 745), the same `backgroundColor.substring(0, 7)` + `'cc'` write (392–393, 791), `fillColor.substring(0, 7)` colour writes (549, 918 — though these force `'80'` instead of preserving alpha, a real difference, not a smell to unify), and `Math.round(v * 100)` percent labels at fourteen sites. So **Task 1's `clipEditorModel.ts`/`clipColorValues.ts` are the shared modules OverlayEditor will later import** — write them without any ClipEditor-specific assumption (plain values in, plain values out, no clip object where a string will do) so the OverlayEditor pass is import-and-delete. What cannot be shared is JSX: `OverlayEditor.module.css` is a different stylesheet with different class names (`sliderRow` vs `transformRow`, `value` vs a bare `<span>`), and both suites assert on class identity, so the section components in Tasks 2–3 stay ClipEditor's alone until someone decides to unify the two stylesheets — which would be a behaviour change, not a refactor. Do not plan OverlayEditor here.
