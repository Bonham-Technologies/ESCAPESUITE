# Performance fixes round 1 (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Land the fixes the profile ranked (see `docs/performance/2026-09-12-profile.md`, "Ranked candidates for Task 4"), each with before/after numbers from `pnpm perf` and the unit ceilings, without changing what the user sees. Ordered by benefit per unit of risk, lowest risk first so the branch always has landable value.

**Measurement discipline (binding for every task):**
- Before touching code, run `pnpm perf` once on this machine and paste the three headline numbers into the task report as "before". After the change, run it twice and paste both (report the median-of-3 the harness gives). A change smaller than the run-to-run band in `docs/performance/2026-09-12-baseline.md` (~1 fps playback, ~1.5% export) is noise: say so, do not claim a win.
- `pnpm test:coverage` must stay green (floors AND the `*.perf.test.ts` ceilings). When a ceiling's measured value drops, LOWER the ceiling to 2× the new value in the same commit (state old→new in the commit body). Never raise a ceiling.
- No user-visible change: the preview must look identical (same composition, same crop, same handle positions) and the exporters' output must be byte-identical for the fixture (the Task 2 export ceilings and `canvasRenderer.*.test.ts` are the guard; for Task 4 add a pixel-level check in the e2e perf spec: sample 5 canvas pixels before/after? — no: use the existing `renderPreview` harness's ordered draw-call assertions — every existing preview test must pass unchanged except where a task's commit explicitly says which assertion changed and why).
- Tests never mock the module under test. Existing preview/exporter test files unchanged unless the task says otherwise.

## Task 1: Stop re-rendering React every animation frame (candidate 2)
- [x] `usePreviewRenderLoop.ts`: `setDisplayTime` per rAF (~511) re-renders the preview subtree ~50×/s and forces a layout each frame. `displayTime` is consumed only by the timecode readout in `PreviewPlayer.tsx` (~259) — confirm with grep. Replace the state with a ref plus a subscription: the hook exposes `subscribeDisplayTime(cb)` (or returns a `displayTimeRef` and a tiny `<Timecode>` component that reads it in its own rAF-driven `useSyncExternalStore`/local state) so only the timecode span updates, at most 10×/s (throttle to 100 ms), while the loop stops calling React state setters per frame. Keep the loop-start/end `setDisplayTime(loopStart|timelineDuration)` semantics (the readout must land exactly on the boundary values). Preview tests that assert the timecode text must still pass (they may need `advanceTimersByTime(100)` — that is a permitted, explained change; list each).
- [x] Re-measure: expect `performWorkOnRoot` to drop out of the top table, layouts per second to fall, rendered fps to rise. Commit: `perf(artist): update the preview timecode without re-rendering the preview each frame` with before/after in the body.

## Task 2: Cheaper blits — `{ alpha: false }` and blur handling (candidate 3)
- [x] `PreviewPlayer.tsx` `getContext('2d')` → `getContext('2d', { alpha: false })` like both exporters; confirm the preview clears to an opaque background every frame (it does: `drawPreviewFrame` fills black first — verify) so no transparency is lost. Re-measure.
- [x] Blur ablation experiment (report only, then decide): run `pnpm perf` with the scene's blur clips temporarily set to blur 0 (local, uncommitted) to measure how much of `drawImage` the `ctx.filter` blur costs. If ≥ 15% of preview JS, implement a per-clip blur bitmap cache in `canvasRenderer.ts`'s clip path keyed by (source frame identity, blur amount, drawn size) with invalidation on any of those changing, used by BOTH preview and export (additive option, default off for export unless the exporter tests stay byte-identical — decide and state). If < 15%, skip and say so.
- [x] Commit(s): `perf(artist): opaque preview canvas` and, if warranted, `perf(artist): cache blurred clip bitmaps between frames`.

## Task 3: Keep the 200 ms playhead write out of the Timeline's render path (candidate 4)
- [x] `Timeline.tsx` reads `currentTime` from the store; each throttled write re-renders the whole timeline (~10% of preview JS, worse with many clips). Move the playhead indicator (and only it) to a small component subscribed to `currentTime`, so the rest of the Timeline does not re-render on playback ticks; audit every `currentTime` read in `Timeline.tsx` (razor preview, snap, keyboard) and route each through either the small component or an on-demand `useEditorStore.getState()` read inside handlers. Timeline tests unchanged. Re-measure `Timeline` render share.
- [x] Commit: `perf(artist): re-render only the playhead on playback ticks`.

## Task 4: Rasterise the preview at display size (candidate 1 — largest, riskiest; do last)
- [x] Today the canvas backing store is `project.resolution` while CSS scales it into the box, so a 4K project rasterises 8.3 Mpx per frame into a ~600 px element. Design: keep ALL scene maths in project space (nothing in `previewGeometry`/`hitTest`/`selectionOverlay`/`drawFrame` changes its coordinate system); size the backing store to the element's CSS box × `devicePixelRatio` (via `ResizeObserver`, already installed for the preview); apply one `ctx.setTransform(k, 0, 0, k, 0, 0)` with `k = backingWidth / project.resolution.width` before drawing each frame; expose `k` so the few places that read `canvas.width` for project-space maths use `project.resolution` instead (audit: `previewGeometry.getCanvasPosition`, `contentBox`, `drawFrame`, `frameCache` keys, `InlineTextEditorAnchor`, `selectionOverlay` handle sizes — handles should stay a constant *screen* size, which today they are not on big projects; decide: keep project-space handle sizes for now, no behaviour change). Export is untouched. Text rendering under a scale transform: font sizes stay in project space (correct); check `measureText` results used by `getOverlayBounds` are transform-independent (they are).
- [x] Guard: every existing preview test passes unchanged (the harness renders into a 960×540 box with a 1280×720 project — expect draw-call arguments to be unchanged because they are in project space; the only new call is the `setTransform` per frame — if the ordered-call assertions include `setTransform`, that is the one explained change). Add a unit test asserting the backing store follows the box × DPR and `k` is applied. Add an e2e visual check to the perf spec: sample the same 9 canvas pixels before/after at one timestamp (tolerance for resampling).
- [x] Re-measure with a 1920×1080 AND a 3840×2160 project (add the resolution as a perf spec parameter; report both). Commit: `perf(artist): rasterise the preview at display size` with numbers for both resolutions.
